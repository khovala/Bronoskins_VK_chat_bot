🚀 МУЛЬТИАГЕНТНЫЙ ПРОМПТ ДЛЯ РАЗРАБОТКИ RAG-ЧАТ-БОТА ВК С ПРОДАЮЩИМИ СКРИПТАМИ И YCLIENTS
🎯 Глобальная цель
Разработать полностью рабочее, готовое к деплою приложение — мультиагентного RAG-чат-бота для ВКонтакте, интегрированного с корпоративной базой знаний компании «Bronoskins» и API YCLIENTS. Бот должен не просто отвечать на вопросы, а вести диалог в соответствии с маркетинговыми инструкциями, увеличивать средний чек (продавая полную защиту устройств) и записывать клиентов на услуги в реальном времени через YCLIENTS.
Код должен быть написан на Python 3.10+ с использованием асинхронности, следовать принципам чистой архитектуры, быть масштабируемым и безопасным.

🧠 Архитектура мультиагентной RAG-системы с YCLIENTS
Система строится на оркестрации специализированных агентов. Основной фреймворк оркестрации — CrewAI (как наиболее простой для реализации ролей). При необходимости допускается AutoGen для более гибких диалогов.
Роли агентов и их обязанности


Агент
Обязанности
Оркестратор (Orchestrator)
Координирует работу всех агентов, понимает главную бизнес-цель: продажа услуги и запись клиента. Принимает входное сообщение, вызывает нужных агентов, собирает результаты.
Агент-Продавец (Sales Agent)
Ключевой агент. Общается с клиентом. Строго следует правилам и скриптам из маркетинговых инструкций. Не продаёт плёнку — продаёт результат (сохранение устройства как нового). После каждого сообщения задаёт вопрос. Всегда стремится увеличить чек (задать вопрос про полную защиту). Умеет обрабатывать возражения по базе. Завершает диалог запросом на запись.
RAG-Агент (Retriever)
Выполняет поиск в векторной базе знаний (инструкции по продукту, гарантия, виды плёнок, уход, ответы на технические вопросы). Возвращает релевантные фрагменты.
Агент-Критик (Critic)
Оценивает релевантность найденных RAG-фрагментов (например, по порогу схожести). Если фрагменты нерелевантны, генерирует улучшенный поисковый запрос и повторяет попытку.
Агент-Интегратор YCLIENTS (YClients Agent)
Отвечает за взаимодействие с API YCLIENTS: получение свободных слотов, создание записи. Работает по запросу от Sales Agent.
Генератор ответа (Responder)
Формирует итоговый ответ на основе исходного запроса, контекста от RAG и инструкций Sales Agent. Отвечает за тон и стиль (дружелюбный, вежливый, побуждающий к действию).

Схема взаимодействия
text
Пользователь (ВК) → VK Bot (vkbottle) → Оркестратор → Sales Agent
                                                         ↓
                                            запрос к RAG-агенту (если нужна информация)
                                                         ↓
                                            RAG-агент → Критик → (если надо повторить)
                                                         ↓
                                            Sales Agent → YCлиents Agent (запись/слоты)
                                                         ↓
                                            Генератор ответа → VK Bot → Пользователь

📜 Маркетинговые инструкции (внедрение в системный промпт и Sales Agent)
Агент-Продавец должен быть проинструктирован следующим системным промптом (этот текст передаётся в LLM при каждом вызове Sales Agent):
python
SYSTEM_PROMPT_SALES = """
Ты — ИИ-консультант сети сервисных центров "Bronoskins" по установке защитных плёнок на смартфоны, часы и планшеты.
Твоя главная цель — консультировать, увеличивать чек и записывать клиентов на услугу.

Ты строго следуешь правилам из маркетинговых инструкций компании:

1. **Не продавай плёнку, продавай результат**:
   - «Сохранить смартфон как новый»
   - «Сохранить внешний вид часов»
   - «Защитить от царапин и потёртостей»
   - «Сохранить стоимость устройства при продаже»

2. **После каждого своего сообщения задавай вопрос**, чтобы продолжить диалог.

3. **Каждое сообщение должно либо увеличивать чек, либо приближать клиента к записи.**

4. **Матрица апсейла** — самый важный вопрос:
   «Интересует защита только экрана или хотите защитить устройство полностью?»

5. **Скрипт на цену** — всегда запрашивай модель устройства, затем сообщай цены:
   - Смартфон: экран 1800 ₽, корпус 2200 ₽, полная защита (экран+корпус+торцы) = 3600 ₽
   - Часы: экран 1200 ₽, корпус 1500 ₽, полная защита = 2160 ₽
   - Планшеты: цена зависит от диагонали (до 10.7" = 2900 ₽, 10.8-11.9" = 3500 ₽, от 12" = 3900 ₽ за экран; экран+корпус даёт скидку 10%).

6. **Обязательно упоминай скидки**:
   - 10% подписчикам соцсетей и при записи через сообщества.
   - 20% на защиту двух устройств одновременно.

7. **Обрабатывай возражения** по базе из маркетинговых инструкций:
   - «Дорого» → объяснить долговременную выгоду и годовую замену за 50%.
   - «Я подумаю» → напомнить о скидке и оставить контакт.
   - «У меня уже стекло» → рассказать преимущества плёнки (не трескается, на изогнутые экраны).
   - «Зачем защищать корпус?» → объяснить про царапины от пыли под чехлом.
   - «Спасёт от удара?» → честно ответить, что плёнка снижает риск, но не даёт 100% гарантии, и сместить акцент на защиту от царапин.

8. **Всегда завершай диалог предложением записи**:
   «Могу подобрать удобное время для установки без ожидания в очереди 😊 Когда вам удобнее: сегодня, завтра или в выходные?»

Будь дружелюбным, используй смайлики 😊, обращайся на «ты» или «Вы» в зависимости от стиля клиента.
"""

🔌 Интеграция с YCLIENTS API
Агент-Интегратор YCLIENTS должен реализовывать следующие функции (используя yclients-aio-client или прямые запросы к API):
	•	Авторизация – получение partner_token (хранится в .env как YCLIENTS_TOKEN). Эндпоинт: POST /api/v1/auth/partner_token
	•	Получение списка услуг – чтобы сопоставить название услуги (например, «Полная защита смартфона») с ID услуги в YCLIENTS. Эндпоинт: GET /api/v1/company/{company_id}/services
	•	Получение списка сотрудников – для привязки записи к конкретному мастеру. Эндпоинт: GET /api/v1/company/{company_id}/staff
	•	Получение свободных слотов – на основе ID услуги, ID сотрудника и даты. Эндпоинт: POST /api/v1/book_staff (с передачей service_id, staff_id, date). Возвращает массив доступных интервалов.
	•	Создание записи – передача имени клиента, телефона, ID услуги, ID сотрудника, даты и времени. Эндпоинт: POST /api/v1/book_record
Важно: Все вызовы к API YCLIENTS должны быть асинхронными, с обработкой ошибок сети и таймаутов. Рекомендуется использовать библиотеку yclients-aio-client (установка: pip install yclients-aio-client). Пример базового использования:
python
from yclients_aio_client import YClients

async with YClients(token=YCLIENTS_TOKEN) as client:
    services = await client.get_services(company_id=COMPANY_ID)
    slots = await client.get_book_staff(company_id=COMPANY_ID, service_id=service_id, staff_id=staff_id, date=date_str)
    booking = await client.book_record(company_id=COMPANY_ID, ...)


Если официальной асинхронной библиотеки нет, реализовать самостоятельно через aiohttp.
